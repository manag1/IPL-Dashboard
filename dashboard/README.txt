Cricket Intelligence - updated IPL Overview

1. Install dependencies:
   pip install -r requirements.txt

2. Set environment variables:
   GEMINI_API_KEY=your_key
   CRICKET_DB_PATH=path_to_ipl.db

3. Run:
   python app.py

Overview changes:
- IPL is represented by Year, not Season or Format.
- Historical franchise names are grouped under one franchise identity.
- Team History shows franchise names and representation periods only.
- Player sidebar role/details are generated by Gemini.
- Match-by-Match, Opposition and Bowler Matchup lists show all rows in scrollable windows.
- Strike Rate by Year has hoverable circular points with year, SR, runs, balls and innings.
- Overview AI payload is intentionally compact and contains NO ball-by-ball data.
- View JSON shows the exact compact payload used for Gemini analysis.


Latest Overview refinements:
- Player sidebar now shows 50s / 100s; 50s are innings scoring 50-99.
- Runs Over Years hover is more forgiving and shows runs, average, strike rate, balls and innings.
- Strike Rate Over Years uses smaller points with a larger hover target and matching tooltip details.
- Runs Distribution now uses Powerplay (1-6), Middle (7-15) and Death (16-20), with runs, average, SR and dots% on hover.
- At a Glance has been removed; Player vs Oppositions now occupies that space with team-specific bars and detailed hover cards.
- Bowler Matchups are sorted by runs scored, descending.
- Dismissal Breakdown uses unique colors and a complete legend with counts and percentages.
- AI Strengths/Weaknesses use compact dashboard styling and the AI prompt requires short, concrete insights.
- The Gemini API key is read from GEMINI_API_KEY instead of being hardcoded in app.py.


Latest requested fixes:
- Player profile team is the player's most recently played franchise, not the first franchise in career chronology.
- Overview KPI order is exactly: Matches, Innings, Highest, Runs, Average, Strike Rate, 50s/100s, 4s/6s, MoM, Catches/Stumpings.
- Legends show labels only; numeric values remain in hover tooltips.
- Chart and opposition hover tooltips are rendered as fixed viewport overlays so they cannot be clipped by scroll containers or pushed into the page scrollbar.
- MoM and catches/stumpings are sourced from database metadata when available, with Cricsheet JSON fallback when the source JSON is present.


RAG CHATBOT
The dashboard includes a Chatbot button wired to the Gemini File Search store in rag_data/store_name.txt. Set GEMINI_API_KEY in the environment before starting Flask. You may override the store with RAG_STORE_NAME.

BOWLERS PAGE
============
Open http://127.0.0.1:5000/bowlers after starting app.py.
The new page uses the existing SQLite schema directly:
- matches / innings / deliveries for all bowling figures
- v_innings_bowling for spell aggregation
- match_players for matches played and team history
- wickets joined through deliveries for credited dismissal types
- is_super_over=0 everywhere in bowling statistics
- deliveries.bowler_wickets for official bowler wickets

New endpoints:
/api/bowler/<player_id>/filters
/api/bowler/<player_id>/overview
/api/bowler/<player_id>/ai-analysis

Shared Stats Template
---------------------
Both /batters and /bowlers now render through templates/stats.html. The route passes dashboard_type and presentation variables, while the shared Jinja template conditionally renders batter- or bowler-specific labels, cards, legends, tables and controls. Use stats.html for future layout/template changes that should affect both dashboards.

RANKINGS MODULE
---------------
Open /rankings to use the IPL Intelligence Rankings module.

Filters:
- Batters
- Bowlers
- All-Rounders
- Teams
- All Seasons or a specific year

The ranking engine is original and ICC-inspired, not an official ICC formula. It uses a match-by-match weighted moving rating with scorecard context, opposition strength, individual opposition quality, scoring environment, match result, workload, not-outs and inferred knockout context. The current database does not store playoff labels, so for full IPL seasons the final four chronological matches are treated as knockout matches.

The ranking API is:
- /api/rankings/filters
- /api/rankings?type=batters&year=all
- /api/rankings?type=bowlers&year=2025
- /api/rankings?type=allrounders&year=all
- /api/rankings?type=teams&year=2025


Rankings filters: The Rankings page supports multi-select Season and Team filters. Multiple teams can be combined with multiple seasons. For player rankings, the team filter shows players who represented any selected canonical franchise during the selected ranking period; the ranking engine continues to calculate contextual ratings from the selected seasons before applying the display filter. For team rankings, the selected team filter limits the displayed teams. Canonical franchise naming is applied to historical team aliases.

RANKING SYSTEM UPDATE
Ratings are now continuous across IPL seasons. Season filters return end-of-period snapshots instead of restarting all players and teams from their base ratings. Team filters constrain displayed entities without changing the underlying league-wide rating environment.

Season page update:
- Seasons are normalized to 2008-2026 and shown as single calendar years.
- No All Seasons option is provided.
- Matches are shown one per row in chronological order from Match 1.
- Added Matches and Points Table tabs for each selected season.

LATEST SEASON PAGE UPDATE
- Points table now marks top four league teams as (Q) and the remaining teams as (E).
- Each team row has an expandable league-only NRR progression, from its first league game to its last league game.
- Knockout labels are season-aware: 2008-2010 use Semi Final 1, Semi Final 2 and Final; 2011 onward uses Qualifier 1, Eliminator, Qualifier 2 and Final.
- Scorecard previews are centred and slightly narrower while retaining one match per row.
